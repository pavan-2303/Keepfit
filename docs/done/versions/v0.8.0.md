## Summary

Keepfit now lets a user authorize their own OpenRouter account without copying
an API key into the app or packaging a developer-funded credential. Assistant
access is optional, visibly bounded to ten dispatched requests per local day,
privacy-disclosed, and isolated from every offline fitness workflow.

## Changelog

- Added system-browser OpenRouter OAuth with S256 PKCE, a one-time localhost
  callback, restart recovery, cancellation, and fail-closed state validation.
- Added Android-Keystore AES/GCM encryption for the token and pending OAuth
  transaction, explicit disconnect, and safe connection inspection.
- Routed assistant inference through the named free Ling model with zero-data-
  retention and data-collection-denial requirements on every request.
- Added an atomic ten-request local-day allowance and access states for invalid,
  revoked, exhausted, unavailable, connecting, and disconnected conditions.
- Added an access ledger and first-use disclosure that explain what is sent and
  what remains on device without showing credential material.
- Removed runtime build-key wiring and excluded sensitive body context from
  assistant prompts and credentials from encrypted backups.
- Updated the application to version `0.8.0` with version code `8`.

## Product Increment Delivered

A user can opt into the assistant with their own OpenRouter account, see the
selected free model and today's remaining allowance, inspect or disconnect the
connection, and cancel an unfinished browser flow. Tracking, drafts, history,
and backups remain usable when access is absent, revoked, exhausted, or offline.

## What Changed

### Created

- OpenRouter PKCE, API, secure credential, callback-server, access-manager, and
  daily-allowance components under `feature:assistant`.
- OpenRouter-backed assistant repository and focused unit/device coverage.
- User documentation for account connection, privacy boundaries, allowance,
  troubleshooting, and release constraints.

### Modified

- Assistant ViewModel, route, and Compose screen - use explicit access state,
  disclosure, browser launch, cancellation, inspection, and disconnect.
- Prompt assembly - excludes weight, BMI, height, measurements, identifiers,
  photos, and raw rows from OpenRouter context.
- App dependency wiring and build metadata - use OpenRouter at runtime and
  remove all build-time assistant-key fields.
- Settings, backup validation, README, architecture, data model, roadmap, and
  initiative state - match the shipped private-access behavior.

### Dependencies

- Added: none. The implementation uses platform networking, browser intents,
  Android Keystore, SharedPreferences, and existing JSON support.
- Removed: no library dependency; obsolete runtime Ollama build-key wiring is
  no longer generated or bound.

## Deviations from Original Plan

| Item | Planned | Actual | Reason |
|---|---|---|---|
| Private callback | Verified Android App Link preferred | OpenRouter-supported `127.0.0.1` callback in the private sideload APK | Keepfit does not yet own the HTTPS domain required for a verified public App Link |
| Model routing | Best free model selected at approval | Retained `inclusionai/ling-3.0-flash-sante:free` | It remained available with tool support and a ZDR endpoint; a named candidate is more repeatable than a changing free-model router |
| Weight context | Optional explicit opt-in was considered | Excluded entirely | The safer approved default avoids adding a sensitive-data control before structured workflows are evaluated |
| Live account verification | Manually grant, revoke, and reconnect where possible | Browser-facing UI and deterministic transitions verified; final grant/revoke awaits the owner's account on the phone | Codex did not have authority or credentials to authorize the owner's OpenRouter account |
