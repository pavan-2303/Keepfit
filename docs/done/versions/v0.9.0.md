## Summary

Keepfit's optional assistant now produces bounded, locally validated coaching
proposals instead of treating model text as commands. Six practical tasks use
required tool calls, sanitized aliases, local safety checks, evidence-first
review, and an explicit approval before any supported fitness-data change.

## Changelog

- Added provider-independent coaching intents, strict tool schemas, complete
  local validation, and fail-closed alias resolution.
- Added weekly summaries/plans, schedule changes, shorter workouts, exercise
  substitutions, and existing-food meal proposals.
- Added a pre-dispatch safety gate for diagnosis, rehabilitation, medication,
  extreme dieting, eating-disorder, and unsafe progression requests.
- Added observed/current/proposed/reason review cards with edit, dismiss, and
  approval-only application.
- Added atomic schedule replacement and validated multi-food diary insertion.
- Added Android-Keystore-encrypted draft/proposal recovery excluded from backup.
- Added a fixed 50-case safety/contract evaluation plus transport, quota,
  provider, persistence, backup, repository, and Compose coverage.
- Updated the app to version `0.9.0` with version code `9`.

## Product Increment Delivered

A connected user chooses a coaching job, adds an optional constraint, and asks
for one reviewable proposal. Keepfit sends only bounded aliases and labels,
rejects unsafe or invalid output, shows the evidence and proposed change, and
writes through existing local repositories only after Apply. Offline tracking
and deterministic plans remain independent of the assistant.
