# Version Spec - v0.24.0 - Assessment-Driven Planning

> **Linked initiative:** [AI-Ready Personal Assessment](../backlog/items/ai-ready-personal-assessment.md)
> **Status:** In progress - frozen 2026-09-17
> **Estimated effort:** 8-12d
> **Risk:** High
> **Prerequisites:** v0.23.0

---

## Sprint Goal

Turn first-run setup into useful planning context and let Coach build a safe,
reviewable first plan even when the personal exercise catalogue is empty.

## Delivered Increment

The guided assessment asks only planning-relevant questions, summarizes the
answers, and preserves manual and offline routes. After OpenRouter is connected,
a person can choose a Coach and request a plan. The AI may reuse personal
exercises or define bounded new ones; applying the reviewed draft creates those
exercise definitions and the plan together in one transaction.

## Work Items

### Item 1 - Focused personal assessment

**Why**

Activity, recovery, schedule, and limitations influence whether a plan is safe
and maintainable more than unrelated setup preferences.

**What to do**

1. Add activity level, sleep, current build, routine challenges, and physical
   limitation fields to the profile-scoped journey record.
2. Reorganize guided setup into clear, single-purpose assessment steps with a
   final review.
3. Keep questions optional where possible and retain offline/manual routes.

**Affected files or subsystems**

- `core:database` journey model and migration
- `feature:workouts` starter-plan model, repository, ViewModel, and UI
- Profile setup and user guidance

**Dependencies**

- Existing profile isolation and guided planning route

**Estimated effort**

- 4-5d

**Done when**

- [ ] Relevant assessment answers survive app restart and profile switching.
- [ ] Setup presents a concise review before choosing a planning route.
- [ ] Existing journey rows migrate with safe defaults.

### Item 2 - AI-created personal exercises

**Why**

An empty personal catalogue should not block an explicitly requested,
reviewed AI plan.

**What to do**

1. Expand the planning context and strict tool contract to support existing
   aliases and validated new exercise definitions.
2. Show which exercises will be added during plan review.
3. Create or reuse normalized exercise definitions transactionally when the
   user applies the plan.

**Affected files or subsystems**

- `feature:assistant` plan models, prompt, contract, validator, and UI
- App assistant context and Room plan applier

**Dependencies**

- v0.23.0 personal catalogue and approval-only plan application

**Estimated effort**

- 3-5d

**Done when**

- [ ] Coach can return a valid plan when the catalogue is empty.
- [ ] Invalid or incomplete generated exercises are rejected before review.
- [ ] Applying a reviewed plan creates reusable personal exercises exactly once.

### Item 3 - Connection-first Coach selection

**Why**

Choosing a persona before OpenRouter is available creates a misleading setup
sequence.

**What to do**

1. Show connection guidance before any Coach persona cards.
2. Reveal Coach selection only after access is connected.
3. Cover disconnected, connecting, and connected states in UI tests.

**Affected files or subsystems**

- `feature:assistant` state-driven Compose UI and tests

**Dependencies**

- Existing OAuth/PKCE OpenRouter connection

**Estimated effort**

- 1-2d

**Done when**

- [ ] No Coach persona is shown while OpenRouter is disconnected.
- [ ] A successful connection leads naturally to Coach selection.
