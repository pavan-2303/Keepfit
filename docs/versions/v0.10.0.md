# Version Spec - v0.10.0 - Guided Journey and Interface Reorganization

> **Linked initiative:** [Practical Fitness Journey and Optional AI Coach](../backlog/items/practical-fitness-journey-and-ai-coach.md)
> **Status:** Approved and frozen for execution
> **Estimated effort:** 10-15d
> **Risk:** High
> **Prerequisites:** v0.9.0 bounded coaching implementation complete

---

## Sprint Goal

Make Keepfit feel like one guided fitness journey instead of a collection of
feature pages: learn the constraints that actually change a plan, lead with one
useful action today, and move setup and management detail out of the daily path.

## Delivered Increment

A new user completes a short, resumable setup covering goals, experience,
availability, session time, location/equipment, movement constraints, and
nutrition preference. Keepfit creates an explainable offline starter routine
from those answers. Returning users use five clear areas - Today, Plan, Log,
Progress, and Coach - while profile, integrations, backup, and administrative
editing live outside the daily navigation.

This version follows the evidence and design direction in the
[fitness app UX benchmark](../references/fitness-app-ux-benchmark.md). It does
not copy competitor branding, screens, or proprietary content.

## Behavioral Contract

- Onboarding asks only questions that can change the deterministic plan.
- Setup is split into focused, plain-language steps, is resumable, and marks
  optional body inputs clearly. Users can skip nonessential questions and edit
  every answer later.
- AI is not required during onboarding. The local plan appears first; a
  connected assistant may offer an alternative only on explicit request.
- The primary navigation has five destinations: Today, Plan, Log, Progress,
  and Coach. Profile and Settings are reachable from a consistent top-level
  action.
- Today shows one dominant next action above the fold. Secondary metrics use
  compact summaries and disclose detail on demand.
- Plan contains schedule, templates, exercises, and adjustments. Log contains
  workout and nutrition capture/reuse. Progress contains weekly review,
  consistency, personal records, measurements, and photos.
- Coach is a query-only conversation. It answers ordinary questions and, when
  the wording calls for it, adds a compact local progress summary to the
  request. It cannot mutate plans or logs in this version.
- Keepfit does not impose a local request allowance. The user's OpenRouter
  account and selected provider own any rate, free-tier, or spending limits;
  provider limit errors remain visible and recoverable.
- Empty, loading, disconnected, and error states never show irrelevant disabled
  forms or oversized administrative controls.
- Existing Room records, backups, offline behavior, history, and deep workflows
  remain compatible. No new network dependency is introduced.
- Screen hierarchy remains usable at 360dp width, large font, and Android 12+.

## Work Items

### Item 1 - Resumable goal-and-constraint setup

1. Replace name-and-height registration with seven focused steps: goal;
   experience/activity; weekly availability; session duration/time; location
   and equipment; movements to avoid; nutrition depth and optional body inputs.
2. Explain why each answer is requested, identify optional questions, support
   Back/Skip/Continue, and persist progress locally after each step.
3. Feed the answers into the existing deterministic starter-plan rules and
   finish with an editable week preview before entering Today.

### Item 2 - Five-part information architecture

1. Replace the old feature destinations with Today, Plan, Log, Progress, and
   Coach; move Settings/Profile to the app bar.
2. Route existing workout management and weekly schedule into Plan, quick
   workout/nutrition capture into Log, and weekly review plus transformation
   evidence into Progress.
3. Preserve navigation state and existing focused workout, review, catalogue,
   backup, and comparison routes.

### Item 3 - Today hierarchy and progressive disclosure

1. Keep one decisive workout/recovery action above the fold with a compact
   rationale and one clear primary button.
2. Replace large dashboard cards with small status rows for nutrition, steps,
   weekly review, and motivation; open detail only when selected.
3. Remove duplicate shortcuts, irrelevant disabled content, and competing
   primary actions from the returning-user path.

### Item 4 - Visual and administrative cleanup

1. Apply one calm training-notebook hierarchy using the benchmarked palette,
   consistent spacing, restrained typography, and reusable compact components.
2. Split the current long Settings page into Profile & goals, Preferences,
   Integrations, Data & backup, and About destinations.
3. Make assistant access a compact status/header and keep model, privacy, and
   connection management available without dominating the conversation.

### Item 5 - Query-first Coach

1. Replace the bounded-task picker and proposal-first layout with a familiar
   message timeline, a bottom composer, useful starter prompts, and a compact
   connection state.
2. Answer general fitness questions and automatically include recent workout,
   nutrition, steps, and progress aggregates only when the question is about
   the user's own history or progression. Make that context use visible.
3. Remove the ten-request local allowance and any quota progress UI. Do not
   retry automatically or hide OpenRouter/provider rate and credit errors.
4. Keep the existing mutation-capable coaching contracts inaccessible from the
   Coach UI for later evaluation; this version is read-only/query-only.

### Item 6 - Usability evidence and compatibility

1. Add Compose tests for first run, resume, starter-plan preview, four-part
   navigation, Today's primary action, Settings categories, and large-font
   scrolling.
2. Run a scripted six-task usability walkthrough: start today's workout, move
   a workout, log a meal, review the week, ask Coach about recent progress, and
   edit a goal.
3. Verify upgrade from v0.9.0, offline launch, backup/restore, screenshots at
   compact and standard phone sizes, lint, unit tests, connected tests, and APK.

## Testing Requirements

- [ ] Observe focused tests fail for the old onboarding and navigation first.
- [ ] Unit-test answer-to-plan rules, optional/skipped answers, and setup resume.
- [ ] Compose-test every setup step and all five primary destinations.
- [ ] Unit-test automatic local-context selection and prove unrelated general
  questions do not include fitness records.
- [ ] Prove repeated user-initiated requests are not blocked by a Keepfit daily
  allowance.
- [ ] Prove the five common tasks start from an obvious action and do not
  require entering Settings.
- [ ] Verify 360dp width, standard phone, 200% font, keyboard, screen-reader
  labels, touch targets, contrast, loading, empty, error, and offline states.
- [ ] Verify existing local data upgrades without reset or history loss.
- [ ] Run repository-wide unit tests, lint, connected suites, and APK install.

## Definition of Done

- [ ] Every work-item checklist is complete.
- [ ] First run produces an editable useful week without AI or a network.
- [ ] Today, Plan, Log, Progress, and Coach match the documented ownership
  boundaries.
- [ ] Coach remains useful with an empty conversation, keeps responses visible,
  and never exposes a data-changing action.
- [ ] One primary action is visually dominant above the fold on Today.
- [ ] The scripted five-task walkthrough passes on a physical-phone-sized
  viewport with no dead ends or irrelevant setup pages.
- [ ] Existing v0.9.0 data, offline flows, assistant safeguards, and backups
  remain intact.
