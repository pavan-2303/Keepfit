## Sprint Goal

Let a user authorize and control their own free OpenRouter access without
pasting a key, exposing a secret, or weakening Keepfit's offline workflows.

## Delivered Increment

The user can review exactly what assistant requests may send, authorize their
own OpenRouter account in the system browser with OAuth PKCE, inspect and test
the connection, use the named free evaluation model within a local daily cap,
and disconnect cleanly. Authentication, quota, provider, and network failures
preserve all local data and drafted input.

## Behavioral Contract

- OpenRouter access is optional and never required for local tracking.
- Authorization uses S256 PKCE, a cryptographically random verifier and state,
  the system browser, and OpenRouter's documented localhost callback for
  local-first apps. A stale, missing, or mismatched state fails closed.
- The OAuth code, verifier, and user-controlled token never enter Room,
  DataStore, application logs, UI text, build configuration, or backup archives.
- The token and any pending OAuth transaction are encrypted with an
  Android-Keystore-backed AES/GCM key before app-private persistence.
- Disconnect erases the token and pending authorization. Revoked and invalid
  credentials become explicit reconnect states without affecting local data.
- The assistant uses `inclusionai/ling-3.0-flash-sante:free` for this evaluation.
  There is no automatic fallback to a paid model or developer-funded key.
- Every inference request requires a user action and includes provider routing
  that denies data collection and requires zero data retention.
- Keepfit allows at most ten dispatched inference requests per local calendar
  day. Connection inspection does not consume this local allowance. The local
  count is not presented as OpenRouter's authoritative account quota.
- No background inference, automatic retry loop, or silent free-to-paid request
  is allowed. Retry is always another visible user action.
- Before authorization, the UI discloses the outbound data categories. Chat
  sends the typed conversation; progress and plan actions additionally send a
  bounded local summary.
- Body weight, BMI, transformation measurements, photos, notes, identifiers,
  and raw database records are excluded. Weight context remains unavailable in
  this slice rather than being transmitted implicitly.
- OpenRouter returns metadata and model output only. Keepfit does not persist
  remote credentials or provider responses in its encrypted backup.
- The existing Ollama adapter remains source-compatible for migration testing,
  but it is not wired to a packaged build-time credential or shown as the
  primary user path.
- Public distribution still requires an owned HTTPS domain and verified
  Android App Link; the private sideload build uses OpenRouter's supported
  loopback callback and clearly documents that release gate.

## Work Items

### Item 1 - Secure OAuth and credential lifecycle

1. Implement PKCE generation, one-time state validation, a bounded loopback
   callback receiver, code exchange, restart recovery, and cancellation.
2. Encrypt the token and pending transaction with Android Keystore AES/GCM.
3. Add connection inspection, revoked/invalid/provider failure mapping, and
   explicit disconnect.

### Item 2 - Privacy and quota adapters

1. Add the ten-request local-day ledger with atomic reservation and next-day
   reset.
2. Require `data_collection: deny` and `zdr: true` on every model request.
3. Keep weight and other sensitive categories out of prompt assembly and prove
   credentials are absent from backup and ordinary preferences.

### Item 3 - Build the access experience

1. Replace build-time-provider copy with a clear OpenRouter access ledger.
2. Add first-use disclosure, connect/connecting/connected/invalid/revoked/quota
   exhausted/provider unavailable/disconnected states.
3. Show the named free model, requests remaining, inspect, reconnect, and
   disconnect actions without displaying token material.

### Item 4 - Integrate, document, and verify

1. Route the existing assistant behaviors through the user-authorized adapter
   and remove packaged assistant credentials.
2. Update application metadata, architecture, privacy guidance, setup docs,
   roadmap, and initiative state.
3. Run focused and broad automated gates, inspect the APK and backup output,
   and manually verify authorization and failure-safe behavior where possible.

## Testing Requirements

- [ ] Observe focused PKCE, quota, OpenRouter request, and access-state tests
  fail before implementation.
- [ ] Unit-test verifier/challenge generation, state mismatch, stale state,
  single-use callback behavior, and error mapping.
- [ ] Unit-test ten requests, the blocked eleventh request, local-day reset, and
  preservation of drafted input.
- [ ] Contract-test request authorization, named model, privacy routing, current
  key inspection, response mapping, invalid token, quota, timeout, and provider
  failure without live network calls.
- [ ] Instrument-test encrypted credential persistence, plaintext absence,
  disconnect erasure, and backup exclusion.
- [ ] Compose-test disclosure and all material connection/quota states.
- [ ] Run `testDebugUnitTest`, `lintDebug`, and `assembleDebug`.
- [ ] Run relevant connected Android suites on API 31 or newer.
- [ ] Inspect the APK for absence of shared provider credentials.
