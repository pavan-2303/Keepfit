> **Linked initiative:** [Practical Fitness Journey and Optional AI Coach](../backlog/items/practical-fitness-journey-and-ai-coach.md)
> **Status:** In Progress
> **Estimated effort:** 8-12d
> **Risk:** High
> **Prerequisites:** v0.2.0 Offline Starter Week, current workout-session flow,
> nutrition summary, optional steps summary, and local reminder settings

## Sprint Goal

Make Today answer one practical question clearly: "What should I do now?" The
user can start, shorten, substitute, reschedule, skip, restore, or resume the
day's workout without changing a reusable template or damaging history.

## Delivered Increment

Today presents one primary workout action derived locally from the active week,
date-specific changes, and any unfinished or completed session. Before changing
the day, the user sees an understandable preview. Confirmed changes survive app
restart, remain reversible where safe, and coexist with the current nutrition,
steps, progress, and reminder context.

## Scope Boundaries

- Keep the feature fully offline and deterministic; do not call Ollama,
  OpenRouter, an exercise catalogue, or any other network service.
- Apply shortening, substitutions, rescheduling, and skipping to a dated
  workout occurrence, never directly to its reusable template.
- Treat an unfinished workout as the primary Today action and do not create a
  second active session.
- Detect the most recent unresolved workout from the preceding seven local
  calendar days and allow a confirmed reschedule through the following seven
  days.
- Allow a rescheduled workout to share a date with an already planned workout;
  show both in the preview and choose one clear primary action at a time.
- Derive completion from the linked workout session instead of storing a second
  mutable completion flag.
- Improve Today hierarchy, labels, empty states, and action ergonomics as needed
  for this workflow. A broad application-wide visual redesign remains deferred.
- Do not add progression logic, post-workout recovery feedback, nutrition-depth
  settings, exercise animations, or AI coaching in this version.

## State and Rule Contract

Today resolves the primary workout state in this order:

1. an unfinished workout session: `RESUME`;
2. a completed occurrence or matching legacy session for today: `COMPLETED`;
3. a confirmed dated occurrence, including a workout rescheduled to today;
4. today's entry from the active recurring weekly plan: `PLANNED`;
5. no applicable workout: `REST_DAY`.

A completed session suppresses another Start action for the same source workout
and date. Independently of the primary state, Today may show the most recent
unresolved planned workout from the preceding seven days as one secondary
`MISSED` recovery choice. Merely opening Today never creates occurrence rows or
marks anything missed.

The supported dated decisions are:

- `FULL`: use the reviewed template exercise order and targets;
- `SHORTENED`: use a deterministic reduced exercise and set selection;
- `MINIMUM`: use the smallest safe deterministic selection that still records
  a meaningful session;
- `SUBSTITUTED`: replace one reviewed exercise with another active local
  exercise while retaining an explicit occurrence snapshot;
- `RESCHEDULED`: move only this occurrence to a confirmed date within seven
  days;
- `SKIPPED`: retain the dated occurrence as intentionally skipped and allow it
  to be restored while no linked session has started.

Variant selection rules and explanations must be centralized, deterministic,
and covered by focused tests. A preview is in-memory UI state and cannot write
to Room. Confirmation performs one validated transaction.

## Work Items

### Item 1 - Persist dated workout occurrences safely

**Why**

The recurring weekly plan describes intent, but day-specific decisions need
their own durable state so they never rewrite templates or historical logs.

**What to do**

1. Add a dated workout-occurrence entity containing nullable source-plan
   provenance, a display-name snapshot, original date, current scheduled date,
   decision type, and audit timestamps. Deleting or replacing a recurring plan
   must not delete a confirmed occurrence.
2. Add occurrence-exercise rows that snapshot the reviewed exercise order,
   targets, and substitutions used for full, shortened, or minimum execution.
3. Link new workout sessions to an occurrence through a nullable, non-cascading
   reference while retaining nullable legacy plan references for existing
   history.
4. Enforce one occurrence per source planned workout and original date while
   provenance exists, valid local dates, canonical decision values, and
   foreign-key integrity for retained records.
5. Increment Room from schema 6 to 7, export the schema, and add a migration
   that leaves all existing plans, templates, sessions, logs, and media intact.
6. Include occurrence records in encrypted backup preview and restore without
   changing credential or media handling.

**Affected files or subsystems**

- `core:database` workout entities, DAO queries, migrations, and schema export
- `feature:settings` backup preview and restore verification
- architecture and data-model references

**Dependencies**

- Existing schema 6 weekly plans, planned workouts, and workout sessions

**Estimated effort**

- 3d

**Done when**

- [ ] Dated decisions round-trip through Room with canonical values.
- [ ] Occurrence snapshots never modify their source template exercises.
- [ ] Migration 6-to-7 preserves existing data and keeps legacy sessions usable.
- [ ] Backup preview and restore retain occurrences and their exercise rows.

### Item 2 - Implement deterministic Today transitions

**Why**

Every Today action must produce a predictable state and protect the single
active-session invariant.

**What to do**

1. Add a provider-independent Today workout state and a focused repository or
   coordinator for resolving recurring plans, dated occurrences, current and
   legacy sessions, and the most recent recoverable missed workout.
2. Define deterministic full, shortened, and minimum exercise-selection rules
   with a plain-language explanation of what changes.
3. Implement preview and confirmed commands for variant selection, one-for-one
   substitution, rescheduling, skipping, and restoring.
4. Validate dates, exercise availability, occurrence ownership, duplicate
   commands, and active-session conflicts before any transaction.
5. Start an occurrence by copying its reviewed exercise snapshot into a new
   session; resume the existing session when one is already active.
6. Derive completed state from the linked completed session, recognize matching
   legacy sessions by plan and local date, and retain skipped or rescheduled
   evidence for future weekly review.

**Affected files or subsystems**

- `feature:workouts` Today models, rules, repository, and ViewModel-facing API
- `core:database` transactional DAO operations
- `app` for cross-feature Today coordination only

**Dependencies**

- Item 1

**Estimated effort**

- 3d

**Done when**

- [ ] State precedence is deterministic for resume, complete, override,
  recurring plan, recoverable missed workout, and rest-day cases.
- [ ] Every mutation validates first and commits atomically.
- [ ] Repeating a confirmed command is safe and does not duplicate occurrences
  or sessions.
- [ ] Custom templates, starter templates, other dates, and history remain
  unchanged by day-specific decisions.

### Item 3 - Build the decisive Today experience

**Why**

The user should understand the next useful action without scanning several
equal-weight cards or opening Workouts first.

**What to do**

1. Replace the current workout summary card with one visually dominant primary
   Today action and concise status text.
2. Provide Start or Resume directly from Today, with secondary actions for
   shorten, minimum, substitute, reschedule, skip, and restore when valid.
3. Show a review sheet or screen containing current state, proposed state,
   affected exercises or date, and reason before confirmation.
4. Show completed, skipped, rescheduled, rest-day, no-plan, error, and offline
   states with a useful next action.
5. Keep nutrition, progress, steps, and reminder context subordinate but
   available; unavailable optional data must not block the workout action.
6. Preserve an unconfirmed preview through configuration recreation and discard
   it safely when the user cancels.

**Affected files or subsystems**

- `app` Today composition, navigation, and app-level state coordination
- `feature:workouts` Today UI components and ViewModel
- `core:designsystem` reuse or small focused component improvements only

**Dependencies**

- Item 2

**Estimated effort**

- 3d

**Done when**

- [ ] Today presents one unambiguous primary action for every resolved state.
- [ ] No preview changes Room until the user explicitly confirms it.
- [ ] A confirmed action updates Today immediately and survives recreation.
- [ ] Large text, TalkBack labels, touch targets, and loading/error states are
  usable on Android 12 and a current Android version.

process recreation, migration, and backup restore before release.
