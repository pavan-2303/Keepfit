# Version Spec - v0.2.0 - Offline Starter Week

> **Linked initiative:** [Practical Fitness Journey and Optional AI Coach](../backlog/items/practical-fitness-journey-and-ai-coach.md)
> **Status:** In Progress
> **Estimated effort:** 8-12d
> **Risk:** Medium
> **Prerequisites:** Existing profile, exercise, workout-template, weekly-plan,
> backup, and Compose navigation foundations

---

## Sprint Goal

Let a new or existing local user record practical workout constraints and
create an understandable, editable starter week without AI, an account, or a
network connection.

## Delivered Increment

From Workouts, the user can open a guided setup, choose a goal, experience
level, available days, session length, equipment, and exercises to avoid,
preview a deterministic week with an explanation, edit its day names and
exercise selections, and explicitly apply it. Applying the proposal stores the
journey preferences and creates a new active weekly plan while preserving
existing exercises, templates, plans, completed sessions, and media.

## Scope Boundaries

- Include the 16 internally authored starter exercise definitions approved in
  the initiative. This version ships instructions but no third-party media.
- Store journey preferences in Room and include them automatically in encrypted
  database backups.
- Mark generated templates with a persisted origin so later regeneration can
  archive generated templates without touching user-created templates.
- Keep the current profile onboarding intact; starter-week setup is a separate,
  repeatable Workouts flow.
- Do not add online exercise lookup, OpenRouter, new analytics, remote calls,
  nutrition planning, Today rescheduling, or AI suggestions.

## Work Items

### Item 1 - Persist journey preferences safely

**Why**

The same choices must be available when the user returns, and generated
content must be distinguishable from personal templates.

**What to do**

1. Add `JourneyProfileEntity` and `JourneyDao` with one journey profile per
   local body profile.
2. Store goal, experience, canonical preferred-day and equipment sets, session
   minutes, avoided starter keys, and timestamps.
3. Add a `CUSTOM` or `STARTER_PLAN` origin to workout templates.
4. Increment Room from schema 5 to 6, export the schema, and add a 5-to-6
   migration that preserves all existing rows.
5. Add journey records to backup preview counts without changing archive
   encryption or restore semantics.

**Affected files or subsystems**

- `core:model`
- `core:database`
- `feature:settings` backup preview
- architecture and data-model references

**Dependencies**

- Existing Room schema 5 and backup implementation

**Estimated effort**

- 2d

**Done when**

- [ ] Journey preferences round-trip through Room with canonical enum values.
- [ ] Migration 5-to-6 preserves existing profile, workout, nutrition, and
  transformation data.
- [ ] Existing templates default to `CUSTOM` and are not modified by starter
  plan regeneration.
- [ ] Backup preview includes journey-profile records and restore retains them.

### Item 2 - Generate a deterministic starter week

**Why**

The core product must create a useful plan without remote inference.

**What to do**

1. Define the 16 starter exercises with original concise instructions,
   equipment support, and stable keys.
2. Validate goal, experience, days, duration, equipment, and avoid selections.
3. Generate one to four balanced sessions using explicit selection, set, and
   repetition rules.
4. Produce a plain-language rationale and deterministic output for identical
   input.
5. Apply the reviewed draft atomically: reuse matching personal exercises,
   create missing starter exercises with UUID identifiers, archive only older
   generated templates, and activate a new weekly plan.

**Affected files or subsystems**

- `feature:workouts` planning models, rules, repository, and tests
- `core:database` workout and journey DAOs

**Dependencies**

- Item 1

**Estimated effort**

- 3d

**Done when**

- [ ] Identical valid inputs produce identical drafts.
- [ ] Equipment and avoided exercises are never violated.
- [ ] Every supported goal, experience level, duration, and day-count path has
  focused tests.
- [ ] Applying a draft creates an active usable week without deleting personal
  templates, older plans, history, or media.

### Item 3 - Build the setup, preview, and edit experience

**Why**

Users need to understand and control the plan before it changes local data.

**What to do**

1. Add a dedicated starter-week route reachable from Workouts.
2. Build a state-driven Compose setup using selectable goal, experience,
   duration, equipment, weekday, and avoid controls.
3. Present validation next to the missing decision and preserve entered state.
4. Show the generated week as a day-by-day rhythm with its rationale.
5. Allow day-name edits plus exercise removal and addition before applying.
6. Require explicit `Use this week` confirmation and show a clear completion
   state.

**Affected files or subsystems**

- `feature:workouts` ViewModel and Compose UI
- `app` navigation and Hilt wiring
- `core:designsystem` reuse only; no speculative theme replacement

**Dependencies**

- Item 2

**Estimated effort**

- 3d

**Done when**

- [ ] A fresh user can go from Workouts to a preview without network access.
- [ ] Back navigation and configuration recreation do not silently apply data.
- [ ] The preview can be edited and only the confirmed version is stored.
- [ ] Returning to setup loads the persisted choices without overwriting the
  current week.
