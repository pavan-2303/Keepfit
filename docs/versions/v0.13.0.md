# Version Spec - v0.13.0 - Flexible Transformation Pose Sets

> **Linked initiative:** [Durable Personalized Fitness Companion](../backlog/items/durable-personalized-fitness-companion.md)
> **Status:** Approved and frozen for execution
> **Estimated effort:** 8-12d
> **Risk:** High
> **Prerequisites:** [v0.12.0 complete](../done/versions/v0.12.0.md)

---

## Sprint Goal

Make transformation check-ins as simple or detailed as each local profile
wants while preserving existing photos, private storage, and meaningful
same-pose comparisons.

## Delivered Increment

A profile starts with four relaxed poses and may enable any of eleven
additional poses. The capture flow shows original neutral guidance, a clear
captured-versus-enabled count, and permits incomplete check-ins. Existing
front, right, back, and left photos migrate without loss, and comparison only
pairs the same stable pose across selected dates.

## Work Items

### Item 1 - Stable pose schema and migration

**Why**

The current four-value angle enum cannot safely grow or provide stable keys
for backup, comparison, and future guidance.

**What to do**

1. Replace persisted angles with the approved 15 stable pose keys.
2. Add profile-owned optional-pose preferences while treating the four basic
   poses as always enabled.
3. Migrate legacy values to their relaxed equivalents and rebuild the unique
   cycle-date-pose constraint.

**Affected files or subsystems**

- `core:database` entities, DAO, migration, schema, and migration tests
- `core:model` pose catalogue

**Dependencies**

- Existing profile isolation and transformation cycles

**Estimated effort**

- 3d

**Done when**

- [ ] Room schema increments and exports successfully.
- [ ] Every legacy photo maps to the correct stable pose without changing its
      cycle, date, path, type, size, or timestamp.
- [ ] Optional pose choices are isolated by profile.

### Item 2 - Flexible guided capture

**Why**

A 15-photo wall would be harder to use than the current four-angle flow.

**What to do**

1. Present only enabled poses as a compact guided sequence grouped by purpose.
2. Show captured/enabled progress and let users skip, revisit, import, or
   replace any pose without blocking the check-in.
3. Add a profile-specific pose selector with the four basic poses clearly
   retained and eleven optional toggles.

**Affected files or subsystems**

- `feature:transformation` models, repository, ViewModel, and Compose UI

**Dependencies**

- Item 1

**Estimated effort**

- 3d

**Done when**

- [ ] New profiles see exactly the four basic poses by default.
- [ ] Optional pose selection survives restart and profile switching.
- [ ] A check-in can remain incomplete and communicates its progress clearly.

### Item 3 - Same-pose comparison and original guidance

**Why**

Comparisons are only useful when the pose matches, and the supplied poster
cannot be redistributed without documented rights.

**What to do**

1. Filter comparison choices to enabled or captured stable poses and pair only
   identical pose keys.
2. Explain which selected date is missing a counterpart and keep date/pose
   switching available.
3. Draw original neutral reference silhouettes and an optional camera alignment
   overlay in Compose, with concise non-judgmental positioning guidance.

**Affected files or subsystems**

- `feature:transformation` comparison and guidance UI
- transformation user documentation

**Dependencies**

- Items 1-2

**Estimated effort**

- 2d

**Done when**

- [ ] No comparison can silently mix different poses.
- [ ] Missing counterparts identify the date and pose.
- [ ] Guidance artwork is original, local, accessible, and does not imply an
      ideal body type.

### Item 4 - Privacy-preserving media and recovery

**Why**

Phone photos can contain location/device metadata and excessive dimensions.

**What to do**

1. Decode, orient, bound, and re-encode supported imports before storing them.
2. Prove the processed copy omits source EXIF location/device metadata and the
   previous file remains until replacement succeeds.
3. Re-run multi-pose encrypted export/restore and missing-media behavior.

**Affected files or subsystems**

- `core:media`
- `feature:settings` backup tests
- `feature:transformation` import handling

**Dependencies**

- Items 1-3

**Estimated effort**

- 2d

**Done when**

- [ ] Stored images are correctly oriented, at most 2048 pixels on either
      side, and contain no copied EXIF metadata.
- [ ] Failed replacement leaves the prior file and database row intact.
- [ ] Encrypted backup round-trips pose keys, preferences, and processed media.
