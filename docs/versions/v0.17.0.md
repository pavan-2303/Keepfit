# Version Spec - v0.17.0 - Persistent Named Coaches

> **Linked initiative:** [Durable Personalized Fitness Companion](../backlog/items/durable-personalized-fitness-companion.md)
> **Status:** Approved and frozen for execution
> **Estimated effort:** 10-12d
> **Risk:** High
> **Prerequisites:** [v0.16.0 complete](../done/versions/v0.16.0.md)

---

## Sprint Goal

Turn Coach from a temporary generic chat into a private, profile-scoped
training relationship with durable conversations, bounded memory, and a choice
of clearly different but consistently safe communication styles.

## Delivered Increment

A person chooses Mira, Rook, or Atlas for a new conversation, continues that
conversation after restart, and can switch among titled conversation threads
without exposing another profile's history. Keepfit sends only the selected
Coach instructions, an explicit bounded memory summary, and the latest 12
messages; the user can rename or delete a thread and clear its future AI memory
while retaining the visible transcript.

## Work Items

### Item 1 - Profile-owned conversation storage

**Why**

Messages currently live only in ViewModel memory, so a restart loses the
conversation and a future multi-Coach experience has no trustworthy ownership
boundary.

**What to do**

1. Add Room conversation and message entities owned through `body_profiles`.
2. Persist stable UUIDs, Coach identifier, title, rolling memory, memory-clear
   timestamp, creation time, and last activity time.
3. Add profile-filtered DAO operations for observe, create, append a completed
   turn, rename, delete, and clear memory.
4. Increment the schema, export it, migrate from v13, and include the new rows
   through the existing database backup paths.

**Affected files or subsystems**

- `core:database` assistant entities, DAO, schema, and migration
- `feature:assistant` conversation repository
- backup, migration, and profile-isolation tests

**Dependencies**

- v0.12.0 profile isolation
- v0.11.0 backup behavior

**Estimated effort**

- 3d

**Done when**

- [ ] Conversations and messages survive process restart and database reopen.
- [ ] Every query and mutation is constrained to the active profile.
- [ ] Deleting a profile removes its Coach history and deleting a conversation
      removes only that conversation's messages.
- [ ] Migration, schema export, backup compatibility, and Room tests pass.

### Item 2 - Named Coach behavior and bounded memory

**Why**

A name without a stable communication contract is decoration, while sending an
unbounded transcript increases cost, latency, and accidental disclosure.

**What to do**

1. Define three local presets: Mira is warm and steady, Rook is concise and
   direct without humiliation, and Atlas is analytical and structured.
2. Add the selected preset as a system instruction while preserving the shared
   safety and general-fitness boundaries.
3. Send at most the latest 12 visible messages plus a deterministic, capped
   rolling memory of earlier messages.
4. Let the user clear future AI memory without deleting the visible transcript
   and explain exactly what will still be stored and sent.

**Affected files or subsystems**

- `feature:assistant` models, prompt assembly, repository, and ViewModel
- privacy/context guidance
- unit and provider-fixture tests

**Dependencies**

- Item 1

**Estimated effort**

- 3d

**Done when**

- [ ] Each Coach produces a distinct system instruction while sharing the same
      safety and privacy rules.
- [ ] Provider history is bounded to a rolling summary and 12 recent messages.
- [ ] Clear memory excludes all earlier messages from later provider requests
      without erasing the local transcript.
- [ ] No Coach can insult, shame, diagnose, or bypass Keepfit approval rules.

### Item 3 - Conversation and Coach experience

**Why**

Long-running chats need lightweight thread management, but the primary Coach
screen should still prioritize reading and asking rather than configuration.

**What to do**

1. Show a compact active-Coach identity and make new chat the clear secondary
   action.
2. Present the three Coaches with short tone samples before a conversation is
   created.
3. Add a quiet conversation drawer for switching, renaming, deleting, and
   clearing memory, with destructive confirmations.
4. Preserve Markdown rendering, connection controls, context disclosure,
   keyboard access, compact width, and large-text usability.

**Affected files or subsystems**

- `feature:assistant` Compose UI and navigation state
- accessibility and Compose tests

**Dependencies**

- Items 1-2

**Estimated effort**

- 3d

**Done when**

- [ ] A user can choose a Coach, start and switch threads, rename a thread,
      clear memory, and delete a thread from the Coach screen.
- [ ] The current Coach and conversation are unambiguous without a large
      settings block consuming the transcript.
- [ ] Empty, disconnected, loading, failure, compact-width, keyboard, and 200%
      text states remain usable.
- [ ] Provider access remains optional and no remote avatar or media is loaded.

### Item 4 - Release verification and guidance

**Why**

Conversation history is personal data and requires the same upgrade, backup,
isolation, and honesty standards as fitness records.

**What to do**

1. Update version metadata, architecture, data model, and user guidance.
2. Verify upgrade, backup/restore, cross-profile isolation, restart continuity,
   memory bounds, and Coach safety wording.
3. Run focused tests, broader suites, lint, assembly, install, launch, and
   installed visual checks.

**Affected files or subsystems**

- Android version metadata
- architecture and user documentation
- automated and manual verification

**Dependencies**

- Items 1-3

**Estimated effort**

- 2d

**Done when**

- [ ] Existing users upgrade without data loss and existing OpenRouter access
      remains valid.
- [ ] Conversation data appears in supported database backup/restore paths and
      secrets remain excluded.
- [ ] Tests, lint, build, install, restart, offline shell, compact width, and
      large-text checks pass.
