# Version Spec - v0.21.0 - Release-candidate Navigation

> **Linked initiative:** [Release-candidate Navigation and Conversation Integrity](../backlog/items/release-candidate-navigation-and-conversation-integrity.md)
> **Status:** In progress - frozen 2026-09-16
> **Estimated effort:** 8-12d
> **Risk:** Medium
> **Prerequisites:** v0.20.0

---

## Sprint Goal

Make Keepfit's primary destinations feel intentional and release-ready while
ensuring Coach history and composer state match explicit user actions.

## Delivered Increment

Plan and Log open on their primary workflows with secondary libraries reached
through clear navigation, templates can be inspected and edited, duplicate
page titles are removed, and Coach creates a visible conversation only after a
question is sent.

## Work Items

### Item 1 - Compact shell and primary hierarchy

**Why**

Duplicate title blocks and excess top spacing obscure the first useful action.

**What to do**

1. Rebuild the shell title treatment around one compact header.
2. Remove redundant screen-local title blocks and normalize top insets.
3. Preserve accessibility at large text sizes.

**Affected files or subsystems**

- `app` navigation shell
- Progress and Settings presentation

**Dependencies**

- Existing field-guide design system

**Estimated effort**

- 2d

**Done when**

- [ ] Every primary destination has one page title and compact content start.

### Item 2 - Plan and Log information architecture

**Why**

Peer tabs expose libraries before the tasks people perform most often.

**What to do**

1. Open Plan on the weekly schedule and move its tools behind navigation.
2. Add template details and identity-preserving edits with catalogue search.
3. Keep Log focused on the diary and move its libraries behind navigation.

**Affected files or subsystems**

- `feature:workouts`
- `feature:nutrition`

**Dependencies**

- Existing Room workout and nutrition repositories

**Estimated effort**

- 4-5d

**Done when**

- [ ] Plan and Log contain no primary tab strip.
- [ ] Templates have detail and edit flows that browse the catalogue.

### Item 3 - Truthful Coach creation and composer state

**Why**

Selecting a Coach currently creates an empty history row, and failed or
restored requests can leave old prompt text in the general composer.

**What to do**

1. Keep a chosen Coach transient until the first question is submitted.
2. Clear the composer immediately when sending.
3. Retain a separate in-memory retry payload and never restore proposal text
   into the general chat field.

**Affected files or subsystems**

- `feature:assistant`

**Dependencies**

- Existing profile-owned conversation repository

**Estimated effort**

- 2d

**Done when**

- [ ] Choosing a Coach does not create a persisted conversation.
- [ ] Sending creates the conversation and clears the composer immediately.
- [ ] Failed sends remain retryable without repopulating the composer.

## Testing Requirements

- [ ] Unit tests cover template updates and Coach state transitions.

- [ ] Relevant unit, instrumentation, lint, and APK builds pass.
- [ ] Primary destinations are visually inspected on the emulator.

- [ ] The delivered increment is usable, not placeholder-only
