# Version Spec - v0.14.0 - Bundled Offline Exercise Catalogue

> **Linked initiative:** [Durable Personalized Fitness Companion](../backlog/items/durable-personalized-fitness-companion.md)
> **Status:** Approved and frozen for execution
> **Estimated effort:** 10-12d
> **Risk:** High
> **Prerequisites:** [v0.13.0 complete](../done/versions/v0.13.0.md)

---

## Sprint Goal

Replace the transient runtime exercise catalogue with one large, searchable,
legally distributable catalogue that is bundled into Keepfit and immediately
usable without internet access.

## Delivered Increment

Every install receives a normalized catalogue built from the metadata and
English instructions at upstream revision
`7455efae41b330c265e7cd4b78dfa848e7ce5ebd`. Catalogue exercises use stable
Keepfit UUIDs, retain source provenance, appear in the ordinary exercise
library, and can be used in templates and plans without copying from a separate
online browser. Gym visual images and GIFs are not imported.

## Work Items

### Item 1 - Reproducible source audit and importer

**Why**

A mutable upstream repository cannot become a trustworthy application
dependency without a pinned, reviewable transformation.

**What to do**

1. Check in the upstream schema, MIT licence, media notice, revision, and file
   hashes used for the import.
2. Add a deterministic build-time importer that validates the source JSON,
   normalizes text and identifiers, removes all media fields, and reports
   duplicates or rejected records.
3. Resolve the seven normalized-name duplicate groups deterministically and
   produce a compact English-only catalogue asset.

**Affected files or subsystems**

- `tools/catalogue`
- `core:database` catalogue assets
- catalogue rights and audit documentation

**Dependencies**

- Pinned upstream revision and PowerShell 7 JSON Schema validation

**Estimated effort**

- 3d

**Done when**

- [ ] Re-running the importer against the pinned revision produces byte-for-byte
      identical catalogue data and audit output.
- [ ] The source validates against its checked-in schema and all accepted rows
      have a stable UUID, source ID, English instructions, and normalized
      metadata.
- [ ] No upstream image path, GIF path, media identifier, or Gym visual asset is
      present in the distributable catalogue.

### Item 2 - Room-owned catalogue and upgrade-safe seeding

**Why**

Exercises must be directly usable by plans, history, and future AI drafts while
remaining authoritative in Room.

**What to do**

1. Extend exercises with source ID, provenance, equipment, target, and
   secondary-muscle metadata.
2. Add a revision ledger and seed accepted catalogue rows transactionally on
   fresh or upgraded databases without overwriting user edits or history.
3. Migrate existing libraries, export the new Room schema, and preserve backup
   compatibility.

**Affected files or subsystems**

- `core:database` entities, DAO, callback, migration, schema, and tests
- workout repository models and mappings

**Dependencies**

- Item 1

**Estimated effort**

- 3d

**Done when**

- [ ] Room schema increments and fresh databases contain the normalized
      catalogue exactly once.
- [ ] Existing exercises, templates, logs, media, edits, and archive state
      survive the upgrade.
- [ ] Catalogue revision and provenance remain queryable and stable across
      restart, backup, and restore.

### Item 3 - One practical, scalable exercise library

**Why**

Separate personal, offline, and live sources are confusing, and eagerly
composing more than one thousand cards would be slow.

**What to do**

1. Remove the source rail and present bundled and user-created exercises in one
   library with clear source and equipment context.
2. Search names, body areas, targets, equipment, secondary muscles, and
   instructions locally, with a lazy result list and useful result count.
3. Keep creation, editing, archiving, local demo attachment, template
   selection, and workout history behavior intact at catalogue scale.

**Affected files or subsystems**

- `feature:workouts` repository, ViewModel, models, and Compose UI

**Dependencies**

- Item 2

**Estimated effort**

- 3d

**Done when**

- [ ] A user can find and use bundled exercises with airplane mode enabled.
- [ ] Search and scrolling remain responsive with the full accepted dataset.
- [ ] User-created exercises and imported private demos remain editable and
      distinguishable from bundled records.

### Item 4 - Remove runtime provider and disclose rights

**Why**

The old ExerciseDB prototype leaks search terms to a provider and duplicates
the new offline experience.

**What to do**

1. Remove ExerciseDB networking, live-result UI, tests, and dependencies that
   exist only for the prototype.
2. Add the dataset copyright and MIT terms to repository and in-app notices,
   explicitly documenting that Gym visual media is excluded.
3. Update architecture, user guidance, version metadata, backup tests, and APK
   verification.

**Affected files or subsystems**

- `app` dependency injection and version metadata
- `feature:workouts`
- `feature:settings` legal information
- project and user documentation

**Dependencies**

- Items 1-3

**Estimated effort**

- 2d

**Done when**

- [ ] Exercise browsing performs no network request and contains no runtime
      ExerciseDB path.
- [ ] Repository and Settings notices include the upstream copyright, MIT
      terms, pinned revision, and media exclusion.
- [ ] Unit, migration, connected, lint, upgrade, clean-install, and APK checks
      pass.
