# Version Spec - v0.22.0 - Practical Template Maintenance

> **Linked initiative:** [Practical Template Maintenance](../backlog/items/practical-template-maintenance.md)
> **Status:** In progress - frozen 2026-09-17
> **Estimated effort:** 4-6d
> **Risk:** Medium
> **Prerequisites:** v0.21.0

---

## Sprint Goal

Replace full-template reconstruction with direct, safe maintenance actions.

## Delivered Increment

Template details expose icon actions for renaming, adding exercises, deleting
the template, editing each exercise prescription, and removing an exercise.
The template list supports explicit multi-selection and confirmed bulk delete.

## Work Items

### Item 1 - Direct template and exercise actions

**Why**

Changing one target or removing one exercise should not require reopening and
rebuilding the whole template.

**What to do**

1. Add accessible icon actions beside the template name.
2. Add target edit and remove actions beside each exercise.
3. Use focused dialogs for rename, add, and prescription editing.

**Affected files or subsystems**

- `feature:workouts` UI, ViewModel, and repository

**Dependencies**

- Existing Room template entities and v0.21.0 Plan navigation

**Estimated effort**

- 3-4d

**Done when**

- [ ] Name, membership, sets, and repetition targets can be changed directly.
- [ ] Icon-only actions have clear accessibility labels and confirmation where destructive.

### Item 2 - Multi-template deletion

**Why**

Cleaning generated or obsolete templates one at a time is unnecessarily slow.

**What to do**

1. Add a deliberate selection mode to the template list.
2. Support select all, clear, and confirmed delete for selected templates.
3. Validate every selected template before one atomic delete operation.

**Affected files or subsystems**

- `feature:workouts` UI and repository
- `core:database` workout DAO transaction

**Dependencies**

- Existing history-protection rules

**Estimated effort**

- 1-2d

**Done when**

- [ ] Several eligible templates can be selected and deleted together.
- [ ] A protected template prevents the whole batch from being partially deleted.

## Testing Requirements

- [ ] Repository instrumentation tests cover direct target edits and atomic bulk delete.
- [ ] Compose tests cover detail actions and list selection mode.
- [ ] Workout tests, lint, debug/release builds, and emulator inspection pass.

## Definition of Done

- [ ] Every work-item checklist is complete.
- [ ] The delivered increment is usable, not placeholder-only.
- [ ] Required tests and verification steps pass.
- [ ] Follow-up work is captured separately rather than left implicit.
