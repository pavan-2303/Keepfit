# Keepfit Data Model

## 1. Conventions

Keepfit uses Room as the structured-data source of truth. All identifiers are
UUID strings generated by the application. All timestamps are UTC instants
stored as epoch milliseconds. Calendar dates use ISO-8601 local-date strings
such as `2026-05-30`.

These conventions make local backups portable and leave room for future sync
without changing primary keys.

Room stores metadata for imported media. Binary files remain in app-private
storage and are addressed by stable relative paths.

## 2. Relationship Map

```text
Exercise 1 --- 0..1 ExerciseMedia
Exercise 1 --- * WorkoutTemplateExercise * --- 1 WorkoutTemplate
WorkoutTemplate 1 --- * PlannedWorkout * --- 1 WeeklyPlan
WorkoutSession 1 --- * ExerciseLog 1 --- * SetLog
Exercise 1 --- * ExerciseLog

Food 1 --- * SavedMealItem * --- 1 SavedMeal
Food 1 --- * FoodDiaryEntry
SavedMeal 1 --- * FoodDiaryEntry

BodyProfile 1 --- * BodyMeasurement
BodyProfile 1 --- * TransformationWeek 1 --- * TransformationPhoto

AssistantConversation 1 --- * AssistantMessage
```

## 3. Workout Domain

### `Exercise`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `name` | String | Required, case-insensitive searchable |
| `muscleGroup` | String | User-selected category |
| `instructions` | String? | Optional personal instructions |
| `notes` | String? | Optional setup notes |
| `isBodyweight` | Boolean | Allows zero weight in set logs |
| `createdAt` | Instant | Creation timestamp |
| `updatedAt` | Instant | Last edit timestamp |
| `archivedAt` | Instant? | Soft-delete marker |

Archive exercises instead of deleting them when history references them.

### `ExerciseMedia`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `exerciseId` | UUID | Unique foreign key to `Exercise` |
| `mediaType` | Enum | `VIDEO` or `GIF` |
| `relativePath` | String | Path below `files/media/exercises/` |
| `mimeType` | String | Validated during import |
| `sizeBytes` | Long | Used for backup summaries |
| `createdAt` | Instant | Import timestamp |

Replacing media creates a new file and updates this record only after the copy
succeeds. Removing an exercise archive does not remove historical exercise
logs.

### `WorkoutTemplate`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `name` | String | Required template name |
| `notes` | String? | Optional description |
| `createdAt` | Instant | Creation timestamp |
| `updatedAt` | Instant | Last edit timestamp |
| `archivedAt` | Instant? | Soft-delete marker |

### `WorkoutTemplateExercise`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `workoutTemplateId` | UUID | Foreign key to `WorkoutTemplate` |
| `exerciseId` | UUID | Foreign key to `Exercise` |
| `position` | Int | Display order |
| `targetSets` | Int | Required positive value |
| `targetReps` | String? | Optional free-form target such as `8-10` |
| `notes` | String? | Optional template-specific note |

### `WeeklyPlan`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `name` | String | Required, for example `Default Week` |
| `startsOn` | LocalDate | Week start date |
| `isActive` | Boolean | At most one active plan in MVP |
| `createdAt` | Instant | Creation timestamp |
| `updatedAt` | Instant | Last edit timestamp |

### `PlannedWorkout`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `weeklyPlanId` | UUID | Foreign key to `WeeklyPlan` |
| `workoutTemplateId` | UUID | Foreign key to `WorkoutTemplate` |
| `dayOfWeek` | Enum | Monday through Sunday |
| `position` | Int | Supports more than one planned workout on a day |

### `WorkoutSession`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `workoutTemplateId` | UUID? | Nullable for an ad-hoc session |
| `plannedWorkoutId` | UUID? | Nullable when started outside a plan |
| `workoutDate` | LocalDate | Local calendar date |
| `startedAt` | Instant | Session start |
| `completedAt` | Instant? | Null while active |
| `notes` | String? | Optional session note |

Only one incomplete session may be active at a time.

### `ExerciseLog`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `workoutSessionId` | UUID | Foreign key to `WorkoutSession` |
| `exerciseId` | UUID | Foreign key to `Exercise` |
| `position` | Int | Exercise display order |
| `notes` | String? | Session-specific notes |

### `SetLog`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `exerciseLogId` | UUID | Foreign key to `ExerciseLog` |
| `position` | Int | Set display order |
| `repetitions` | Int | Required non-negative value |
| `weightKg` | Decimal | Required non-negative value |
| `isCompleted` | Boolean | Supports editing an active session |

Personal records are derived from completed sets rather than stored as mutable
records. MVP records include highest logged weight and highest repetitions for
an exercise.

## 6. Settings and Goals

### `UserGoal`

single `BodyProfile` row until the settings feature needs a broader goal model.

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `bodyProfileId` | UUID | Foreign key to `BodyProfile` |
| `dailyCalories` | Decimal? | Optional |
| `dailyProteinGrams` | Decimal? | Optional |
| `dailyCarbohydrateGrams` | Decimal? | Optional |
| `dailyFatGrams` | Decimal? | Optional |
| `targetWeightKg` | Decimal? | Optional |
| `weeklyWorkoutCount` | Int? | Optional |
| `updatedAt` | Instant | Last edit timestamp |

### `AppSetting`

Store simple local settings in DataStore rather than Room:

- preferred weight unit;
- preferred measurement unit;
- week start preference;
- workout reminder settings;
- weekly transformation reminder settings;
- rest timer duration;
- phase-2 optional integration toggles.

Tokens and secrets do not belong in DataStore. Use Android secure credential
storage for phase-2 Ollama credentials.

## 8. Deletion and Retention Rules

- Archive exercises, foods, and workout templates referenced by history.
- Cascade-delete template children when deleting an unused template.
- Cascade-delete set logs and exercise logs when deleting a workout session.
- Cascade-delete saved meal items when deleting a saved meal.
- Delete transformation photo files only after their Room records are removed
  successfully.
- Include archived records in backup exports.
- Keep backup restoration all-or-nothing.

## 9. Migration Rules

- Increment the Room schema version for every schema change.
- Export Room schemas into version control.
- Add migration tests before shipping an upgrade.
- Never reuse a removed column name for a different meaning.
- Version the backup manifest independently of the Room schema.
