## Summary

Add compact local profile management and enforce active-profile ownership at
Room, DataStore, repository, backup, and UI boundaries while retaining shared
exercise and food reference libraries.

## Checklist

- [x] Room 11 migration assigns existing personal records to the original
      profile and preserves shared libraries.
- [x] Active profile and profile-owned preferences survive restart and repair
      invalid selections.
- [x] Personal repositories cannot read or mutate another profile's records.
- [x] Avatar menu supports add, switch, edit, and safe archive.
- [x] Screens react to profile switches without restarting the application.
- [x] Encrypted backup round-trips all profiles and active-profile state.
- [x] Migration, regression, lint, upgrade, and APK checks pass.

## Decisions and Deviations

| Date | Decision / Deviation | Reason |
|---|---|---|
| 2026-09-14 | Add ownership to personal root tables rather than every child row | Foreign-key ancestry gives one authoritative owner and avoids duplicated identifiers drifting out of sync. |
| 2026-09-14 | Keep OpenRouter credential recovery device-level | It protects one device credential rather than fitness history; Coach conversations become profile-owned in v0.17.0. |
| 2026-09-14 | Keep exercises and foods shared, but saved meals personal | Reference libraries are reusable; plans, diary choices, and saved combinations represent one person's behavior. |
| 2026-09-14 | Version the encrypted-backup manifest independently as format 2 while continuing to accept format 1 | New archives preserve every profile's settings and active selection without breaking existing backups. |
