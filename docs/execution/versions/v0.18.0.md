## Summary

Add strict catalogue-backed AI workout drafts, a legible preview, and an
atomic approval path while exposing existing manual schedule and saved-food
reviews without allowing silent changes.

## Checklist

- [x] Provider output can reference only supplied active exercise UUIDs.
- [x] Invalid or unsafe output fails closed before any local change.
- [x] Approval replaces the weekly plan atomically for the active profile.
- [x] Onboarding and Coach can start the same planning flow.
- [x] Draft and manual reviews remain preview-only until explicit approval.
- [x] Failure, compact-width, large-text, privacy, and regression checks pass.
- [x] Documentation, lint, build, package, connected, install, launch, and
      visual checks pass.

## Progress Log

**2026-09-16** - Froze v0.18.0 after the product owner asked to continue to
the next roadmap item. v0.17.0 implementation is retained unchanged and its
separate connected-device verification debt remains open.

**2026-09-16** - Chose a training-docket visual direction. Keepfit's existing
field green, action orange, slate, paper, white, and ink palette remains
authoritative. The memorable element is one vertical weekly rail: weekday,
session name, exercise order, and targets read as a single training document.
The transcript and connection row stay quiet around it, and apply/dismiss
actions use plain verbs in a stable review footer.

**2026-09-16** - Reviewed the design against the brief and removed a proposed
grid of equal plan cards. A grid made the plan feel like another dashboard and
hid workout order; the vertical rail reflects how a week is actually read and
scales more predictably at compact width and large text.

**2026-09-16** - Implemented a strict `create_workout_plan` tool contract,
bounded bundled-catalogue planning context, local resolver, unknown-ID and
target validation, and pre-network safety refusal. Custom exercise identifiers
and private fitness identifiers are excluded from this planning request.

**2026-09-16** - Replaced the incremental name-based plan applier with a single
Room transaction. Approval revalidates bundled exercises, writes exact targets
and order, affects only the active profile, and cannot deactivate the current
plan unless the whole replacement succeeds.

**2026-09-16** - Added the compact Coach plan workspace, vertical review rail,
explicit apply/revise/dismiss controls, weekly and saved-food review entry, and
onboarding handoff. Disconnected onboarding waits for OpenRouter connection
before opening the planner.

**2026-09-16** - Updated architecture, privacy disclosure, user guidance, and
Android metadata to version 0.18.0 (code 18). Repository unit tests, lint, and
debug assembly pass. The generated APK reports version 0.18.0/code 18.

**2026-09-16** - Completed Android 16 device verification. The atomic Room
applier passed rollback, exact-target, and active-profile isolation checks; the
Coach and onboarding Compose suites passed; and the full Coach, database, and
settings connected suites remained green. A fresh install was walked through
profile setup, all seven survey steps, the planning chooser, the AI path, Coach
selection, and the connect-first OpenRouter disclosure. OAuth was deliberately
not started, so no external account or credential was created.
