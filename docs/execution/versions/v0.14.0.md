## Summary

Replace the transient runtime catalogue with a pinned, audited, normalized,
Room-owned exercise catalogue that remains fully usable offline.

## Checklist

- [x] Import output and audit report are deterministic at the pinned revision.
- [x] Accepted rows have stable UUIDs, provenance, metadata, and English guidance.
- [x] No Gym visual media or media references enter the distributable asset.
- [x] Room migration and idempotent seeding preserve existing user data.
- [x] One lazy exercise library searches the complete catalogue locally.
- [x] Runtime ExerciseDB code is removed and legal notices are accurate.
- [x] Regression, migration, backup, lint, install, offline, and APK checks pass.

## Progress Log

**2026-09-15** - Froze v0.14.0 after auditing upstream revision
`7455efae41b330c265e7cd4b78dfa848e7ce5ebd`. Its JSON validates against the
published schema and contains 1,324 unique source IDs, ten body areas, 28
equipment values, complete names and English instructions, and seven
normalized-name duplicate groups. Confirmed that metadata/instruction text is
MIT-covered while Gym visual images and GIFs require separate rights and will
be excluded.

**2026-09-15** - Added the pinned PowerShell importer and independent verifier,
added the normalized catalogue, audit report, upstream schema, licence, and
notice, and verified byte-for-byte deterministic regeneration. All accepted
records use stable UUIDs and exclude upstream media fields and files.

**2026-09-15** - Added Room schema 13, catalogue provenance columns, an import
ledger, the 12-to-13 migration, and transactional idempotent first-open seeding.
Existing user exercises and edits survive upgrades and subsequent opens.

**2026-09-15** - Replaced the separate runtime-provider experience with one
lazy Room-backed exercise library. Search now covers name, body area, equipment,
target, secondary muscles, and English instructions. Exercise details disclose
source and licence while retaining private user-added demonstration media.

**2026-09-15** - Extended encrypted backup and restore to preserve catalogue
provenance and the import ledger, added the in-app legal notice, and retired the
runtime ExerciseDB provider, network dependency, and obsolete tests.

**2026-09-15** - Verified deterministic import, unit tests, lint, debug assembly,
Room migration and backup behavior, catalogue UI, v0.13-to-v0.14 upgrade, and a
fresh first launch in airplane mode. Batched seeding reduced clean offline cold

post-seed cold start was about 8 seconds.

## Decisions and Deviations

| Date | Decision / Deviation | Reason |
|---|---|---|
| 2026-09-15 | Seed normalized records into Room instead of exposing a second asset-only browser | Plans, history, manual edits, and future AI drafts can use the same stable exercise identifiers. |
| 2026-09-15 | Retain English instructions only for this version | Other translations require a separate quality review before they become user-facing. |
| 2026-09-15 | Remove every upstream media field as well as the media files | Avoids accidental reliance on Gym visual material without a Keepfit licence. |
| 2026-09-15 | Accept 1,316 canonical records after resolving eight duplicate groups | The executable normalization test found one punctuation-equivalent pair omitted by the initial exploratory query. |
| 2026-09-15 | Seed in batches of 1,024 records inside one transaction | This keeps the one-time import near normal launch time while remaining below the Android 12 SQLite host-parameter limit. |
| 2026-09-15 | Preserve user-created records on identifier collision | Catalogue installation must never overwrite local work during an upgrade. |
