## Summary

Add narrowly scoped, device-dependent Android recovery for structured records
and non-secret preferences while keeping private media and credentials out of
normal backup and preserving the complete encrypted export path.

## Checklist

- [x] The installed application participates in Android backup.
- [x] Cloud and device-transfer rules allowlist only the Room database and
      non-secret DataStore file.
- [x] Secure preferences, OAuth state, drafts, media, caches, and other files
      remain outside the platform-backup allowlist.
- [x] Missing restored media is handled without crash or silent metadata loss.
- [x] Recovery guidance is accurate and does not promise guaranteed restore.
- [x] Optional credential recovery is opt-in, validated, revocable, and safe
      when Block Store is unavailable.
- [x] Manual encrypted backup remains the complete recovery path.
- [x] Reinstall launch, scoped regression, lint, and APK checks pass; the known
      API 36 Health Connect immediate-aggregate test limitation is recorded.

## Progress Log

**2026-09-14** - v0.10.0 closed after the Coach Markdown phone-review
correction passed its focused and release gates. Froze v0.11.0 from the approved
initiative and began with the platform backup policy. Android's current contract
confirms that include rules become an allowlist, Android 12+ requires
data-extraction rules, automatic backups are device- and schedule-dependent,
and Block Store is the appropriate separate credential-recovery mechanism.

**2026-09-14** - Added a failing installed-app instrumentation test that found
backup disabled and both policy resources absent. Enabled backup with an exact
two-path allowlist for `keepfit.db` and
`datastore/keepfit_settings.preferences_pb` across encrypted cloud backup and
device transfer. Because no shared-preference or broad file include exists,
credentials, OAuth state, encrypted assistant drafts, exercise media, and
transformation photos remain excluded. Bumped the in-progress app build to
version 0.11.0/code 11.

**2026-09-14** - Added honest Data & backup guidance distinguishing
device-dependent automatic recovery from complete encrypted export. Existing
exercise media resolution already returns no demo when a restored file is
missing; transformation previews now distinguish an absent capture from a
restored record whose private file is unavailable and point to encrypted
restore without deleting metadata.

**2026-09-14** - Added disabled-by-default credential-recovery consent to the
non-secret settings store and a focused recovery coordinator. A recovered token
is size-checked, validated against OpenRouter, and only then copied into the
Keystore-backed local credential store. Existing local access is never
overwritten; invalid or revoked recovery data is erased; transient provider
failure keeps it available for retry; opt-out and disconnect withdraw consent
and attempt deletion.

**2026-09-14** - Integrated Google Play services Block Store under one
Keepfit-specific key. Device-to-device/local recovery remains possible on a
supported service, while cloud token backup is requested only when Block Store
reports end-to-end encryption. Settings exposes a compact recovery switch and
clear reconnect fallback. The real API 36 adapter test stored, retrieved, and
deleted its isolated token successfully. A regression also proves that a token
recovered after dependency creation refreshes Coach from disconnected to
connected immediately.

**2026-09-14** - Corrected the repository ignore pattern that accidentally
excluded the `core/media` source module along with local media. The root-only
ignore now keeps user media private while allowing the source module and its
missing/escaping-file instrumentation tests into version control.

**2026-09-14** - Exercised Android Backup Manager on the API 36 emulator. The
Google device-transfer transport accepted the scoped backup after the app was
launched, but its command-line restore returned transport result `-1000` after
uninstall/reinstall, so automatic end-to-end restoration was not claimed. The
original Google transport selection and disabled Backup Manager state were
restored. Fresh install and launch passed with version 0.11.0/code 11 and the
installed package reports `ALLOW_BACKUP`.

**2026-09-14** - Final scoped device suites passed for the installed backup
policy, missing exercise/transformation media, Coach Markdown and Block Store,
and Settings encrypted-backup/UI flows. The repository-wide unit, lint, and
debug assembly gate passed 674 Gradle tasks. The broader connected run reached
the existing API 36 Health Connect aggregate timing failure documented in
v0.10.0; it was not changed or represented as a v0.11 regression pass.

## Decisions and Deviations

| Date | Decision / Deviation | Reason |
|---|---|---|
| 2026-09-14 | Allowlist exact Room and DataStore paths instead of broadly excluding known secrets | New files remain private by default and cannot accidentally enter backup later. |
| 2026-09-14 | Use the same narrow allowlist for cloud and device transfer | Credentials, private photos, and imported media require explicit user-controlled recovery regardless of transport. |
| 2026-09-14 | Keep Block Store behind explicit consent and token validation | Platform credential recovery is optional and cannot be treated as proof that a recovered token is still valid. |
| 2026-09-14 | Request Block Store cloud backup only with reported end-to-end encryption | A recovered AI credential must not trade reinstall convenience for weaker storage protection. |
| 2026-09-14 | Treat Backup Manager restore result `-1000` as an emulator transport limitation | The frozen scope requires recording platform limitations and forbids promising universal Android restore. |
