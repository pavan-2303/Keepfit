## Summary

Create one restrained training-field-guide identity across Keepfit's core
journeys, then add motion and haptics only where they explain or confirm a
state change.

## Design Direction

**Subject and job**

Keepfit is a private training log used between real sets, meals, and check-ins.
It should read like a calm field guide and session docket: quick to scan with
one hand, serious about records, and encouraging without badges or spectacle.

**Token plan**

| Role | Token |
|---|---|
| Field green | `#196B4A` - primary state, selected navigation, confirmed work |
| Interval orange | `#D9772B` - one next action or timing emphasis |
| Paper | `#F7F8F3` - low-glare app background |
| Chalk | `#FFFFFF` - reading surfaces and input areas |
| Training slate | `#496456` - supporting status and structure |
| Ink | `#18201B` - primary text and high-contrast icons |

Typography remains an offline-safe Android sans family. Heavy, tightly spaced
display styles carry short session headings; regular body styles carry longer
guidance with comfortable line height. This avoids a bundled-font payload and
keeps Android fallback and 200% text behavior predictable.

**Layout concept**

```text
TODAY                         [profile]
Monday, 16 September

| current training state
| session name and useful detail
| [one primary action]

weekly evidence
quiet supporting rows

Today   Plan   Log   Progress   Coach
```

Content remains left aligned. One vertical pace line identifies the decisive
area; supporting content uses dividers and tonal bands instead of a grid of
identical floating cards.

**Principles**

1. One screen gets one visually dominant action.
2. Lines, color, and numbering encode real order or state.
3. Sentence case replaces decorative all-caps labels.
4. Motion belongs to navigation, expansion, progress, or confirmed completion.
5. The static state remains fully understandable when motion is reduced.

**Brief review**

The first pass used a soft gradient hero and several rounded cards. That could
belong to any wellness dashboard and repeated the app's current clumsiness.
The revised direction removes gradients and spends the visual emphasis on one
training pace line, stronger typographic rhythm, and a compact action band.
Surrounding surfaces stay quiet so logs, responses, and targets remain primary.

## Decisions and Deviations

| Date | Decision / Deviation | Reason |
|---|---|---|
| 2026-09-16 | Retain the established green, orange, paper, slate, and ink palette | Continuity matters; distinctiveness will come from hierarchy, the pace line, typography, and motion rather than a gratuitous recolor. |
| 2026-09-16 | Keep system-local sans typography | Avoids remote font loading and a new binary/licensing surface while preserving reliable Android fallback and large-text behavior. |
| 2026-09-16 | Remove the prior gradient hero direction | A gradient and equal rounded cards read as a generic wellness dashboard and competed with the actual workout state. |
| 2026-09-16 | Treat AVD frame figures as diagnostic, not a physical-phone benchmark | The owner already identified this AVD as unusually slow; reduced motion improved the sample, but a representative phone remains the meaningful performance gate. |
